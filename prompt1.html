# Task: Transform Low-Fidelity Wireframes into High-Fidelity UI Designs

Act as a Senior UI/UX Designer, Product Designer, and Design Systems Expert.

Your task is to transform the attached Low-Fidelity Wireframe into a polished, production-quality High-Fidelity UI Design, using all attached content, images, brand assets, and visual references.

## 1. Understand the Attachments

I may provide the following materials:

  • Low-Fidelity Wireframe: The primary structural reference defining layout, hierarchy, component placement, and user flow.
  • Content References: Text, images, product information, features, data, and other content that must appear in the final design.
  • Visual References: Screenshots or designs that communicate the desired aesthetic, interaction patterns, or visual direction.
  • Brand Assets: Logos, colors, typography, icons, illustrations, and other identity elements.

Analyze all attachments before designing. Determine the purpose of each image and use it accordingly. Do not confuse content references with layout references.

If critical information is missing or contradictory, ask concise clarification questions before proceeding. Otherwise, make thoughtful, professional design decisions.

## 2. Preserve the Original Wireframe Structure

Treat the supplied Low-Fidelity Wireframe as the primary source of truth for layout and information architecture.

  • Preserve the main layout, content hierarchy, section order, component placement, and intended user flow.
  • Maintain relationships between elements and their relative visual positions.
  • Do not arbitrarily remove, add, reorder, or relocate major sections.
  • Preserve all important functionality implied by the wireframe.
  • You may refine spacing, alignment, sizing, proportions, and component styling to improve usability and visual quality.
  • If a structural change is necessary to solve a genuine usability issue, explain why rather than making an unexplained redesign.

The objective is to elevate the existing wireframe, not replace its underlying design decisions.

## 3. Use the Provided Content Accurately

  • Use the attached content as the source of truth.
  • Include all relevant text, images, data, labels, and content specified in the references.
  • Preserve the original meaning of all text.
  • Do not invent products, statistics, testimonials, features, or unsupported information.
  • Do not replace meaningful content with generic placeholder text.
  • Use supplied images and brand assets where appropriate.
  • If an asset is missing, use a suitable temporary placeholder and clearly identify it.

Ensure that the resulting interface feels like a real, coherent product rather than a decorative mockup.

## 4. Transform the Wireframe into High-Fidelity UI

Visual Design

  • Establish a clear visual hierarchy through typography, scale, contrast, spacing, and color.
  • Create a cohesive color palette appropriate to the supplied brand and references.
  • Use consistent typography with suitable font sizes, weights, line heights, and text lengths.
  • Apply a consistent spacing system, grid, alignment, and layout rhythm.
  • Design polished buttons, inputs, cards, navigation elements, tabs, menus, and other components.
  • Use appropriate borders, shadows, radii, backgrounds, and visual effects without unnecessary decoration.
  • Ensure that icons, illustrations, and images share a consistent visual style.

UX Quality

  • Maintain clear navigation and intuitive interaction patterns.
  • Make primary and secondary actions visually distinguishable.
  • Ensure that content is easy to scan and understand.
  • Provide appropriate visual feedback for interactive elements.
  • Maintain readable contrast, accessible typography, and sufficiently large interaction targets.
  • Avoid visual clutter, inconsistent components, excessive gradients, and decorative effects that harm usability.

## 5. Follow the Visual References Intelligently

Use the supplied visual references to understand the intended aesthetic, not to copy unrelated layouts blindly.

Extract relevant characteristics such as color palette, typography, component styling, spacing, density, image treatment, borders, shadows, surface styles, and overall brand personality.

Combine these characteristics with the original wireframe and actual content to create a unified design.

If no visual references are supplied, choose a modern, professional visual direction that fits the product's purpose and audience.

## 6. Make the Design Complete and Consistent

  • Design the entire supplied screen or set of screens, not just the hero section or first viewport.
  • Preserve consistency across all screens.
  • Reuse components and visual patterns wherever appropriate.
  • Ensure realistic content density and balanced whitespace.
  • Prevent text clipping, overlapping elements, awkward wrapping, and inconsistent alignment.
  • Respect the intended platform, such as desktop web, mobile web, or a mobile application.
  • If the target viewport is not specified, infer it from the wireframe and ask only if the choice materially affects the result.

## 7. Final Quality Check

Before presenting the result, verify that:

  1. The original wireframe structure has been respected.
  2. All supplied content has been incorporated appropriately.
  3. The design follows a consistent visual language.
  4. Every major component looks intentionally designed.
  5. The information hierarchy is clear.
  6. The interface is visually polished, realistic, and usable.
  7. No unsupported content or unnecessary sections have been introduced.
  8. The result looks like a genuine, professional High-Fidelity UI design rather than a colored wireframe.

## 8. Deliverable

Produce the actual High-Fidelity UI Design based on the supplied attachments.

Do not merely describe the proposed design or provide a list of suggestions.

If your environment supports direct visual generation, generate the finished interface. If it supports a design canvas, create the design there. If it supports editable code or design files, preserve the result in an editable format when possible.

If you cannot directly create the requested design in your environment, clearly state that limitation and provide the most suitable alternative.

Final priority: Fidelity to the original wireframe, accuracy of the supplied content, excellent usability, and professional visual execution—in that order.
